# Правила работы над EnergyTool

- Перед изменениями прочитайте [ТЗ](docs/MVP-SPEC.md), [архитектуру](docs/ARCHITECTURE.md) и [ручную приёмку](docs/TODAY-CHECKLIST.md). Для контракта запуска этапа 1 используйте технический регламент, для сценария консультации — кейс, для предметных утверждений — предоставленную базу знаний.
- Сохраняйте `solution.py` как точку входа. Для платформы нужны только корневые Python-модули и `requirements.txt` с зафиксированными разрешёнными зависимостями. Зафиксируйте команды запуска и проверки в README по мере реализации.
- Сначала согласуйте контракт изменения, затем реализуйте небольшой проверяемый шаг. По §8–9 ТЗ поручайте субагентам искать, исправлять и перепроверять технические баги во время разработки и после тестов. Записывайте все ошибки поиска и ответов в `.local/косяки точности ответов ассистента.md`. Передайте пользователю файл с рекомендациями после технической приёмки.
- Материалы кейса используются для задания. Не публикуйте исходные выгрузки и копии и не передавайте их третьим лицам. Храните данные и артефакты прогонов локально. Используйте только тестовые или выдуманные персональные данные. Ключи, реальные контакты и полные диалоги не включайте в Git, архив сдачи или логи.
- Никогда не выполняйте `git commit` или `git push` без прямого указания пользователя на соответствующее действие. После реализации крупной функции предложите пользователю сделать коммит. Используйте Conventional Commits и не добавляйте строки `Co-Authored-By`. Не указывайте Codex или GPT в соавторах.
