# Архитектура первой версии EnergyTool

Один запуск читает вопросы и базу знаний, отвечает на каждый вопрос отдельно и записывает общий CSV.

```text
knowledge-base.zip → фрагменты → индекс ─┐
                                        ├→ поиск → лучшие фрагменты
questions.csv → последняя реплика ────────┘                │
                      │                                  ↓
                      └── реплика и история ───────────→ Qwen
                                                         │
submission.csv ← проверка ответа ←────────────────────────┘
```

1. **Подготовка базы.** При запуске Python один раз читает Markdown и TXT из ZIP. Он делит документы на фрагменты и сохраняет заголовки, таблицы и условия применимости.
2. **Поиск.** Код ищет по последней реплике и относящимся к ней фактам из диалога. Базовый поиск работает по словам. Эмбеддинги могут найти похожий смысл, реранкер может переставить кандидатов. При сбое этих сервисов поиск продолжается локально.
3. **Консультация.** Одна модель получает вопрос, нужную часть истории и лучшие фрагменты. Она объясняет подходящий продукт, задаёт конкретное уточнение или предлагает разговор со специалистом. Например, если клиент не готов оставить телефон, консультант объясняет, какие данные нужны для оценки.
4. **Выдача.** Скрипт проверяет, что ответ непустой и проходит по длине. Если отдельный запрос упал, этому ID достаётся нейтральный ответ. В CSV сохраняются исходные ID и их порядок.

В коде `solution.py` управляет запуском, `retrieval.py` отвечает за базу и поиск, `consultant.py` — за работу с репликой и ответ, `llm_client.py` — за прокси. Контракты и тесты позволяют менять поиск отдельно от текста консультации.

Первая сборка использует один генеративный вызов на предметный вопрос. Лимит 20 минут относится ко всему запуску, а объём скрытого набора неизвестен. Эмбеддер и реранкер можно включить после проверки качества и скорости. Веб-чат, история отдельных сессий и создание заявки относятся к следующему этапу.

Детали реализации и критерии проверки описаны в [ТЗ](MVP-SPEC.md).
