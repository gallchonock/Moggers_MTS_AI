## Что посмотреть в коде своими руками

- [ ] **`solution.py`.** Найдите точку входа и проверьте, что она читает два файла из `DATA_DIR`, строит индекс один раз и пишет CSV в текущую папку. Посмотрите, как индекс позиции связывает ответ с исходным ID при параллельной обработке. Убедитесь, что отдельный сбой приводит к ответу по этому ID, а дедлайн оставляет время на запись файла.
- [ ] **`retrieval.py`.** Найдите чтение ZIP, нарезку, индекс и окончательный отбор. В нарезке должны остаться заголовок, текст и путь. Проследите один факт из середины длинного файла и одну строку таблицы с оговоркой до фактического контекста модели. В выдаче должны быть относящиеся к задаче источники, а пустое совпадение не должно заполняться случайным текстом.
- [ ] **`consultant.py`.** Посмотрите, какая реплика берётся для поиска, какие предыдущие факты остаются и что передаётся в prompt. Для ID 18 модель должна видеть три склада, около 40 счётчиков и отказ оставить телефон. Убедитесь, что инструкция требует опираться на материалы, разрешает уточнить недостающее и ведёт к менеджеру только по делу.
- [ ] **`llm_client.py`.** Проверьте ID модели, ключ и URL из окружения, один штатный chat-вызов, ограниченный повтор при временном сбое и остановку при 401. Дополнительные API должны использовать тот же прокси и иметь локальный запасной путь. Сравните код с [архитектурой](ARCHITECTURE.md).
- [ ] **README и `requirements.txt`.** Пройдите инструкцию как новый участник. Достаточно данных, Python и зависимостей из pinned-файла. В коде нет установки пакетов. Посмотрите, что секреты, входные материалы, индексы и ответы отсутствуют в изменениях Git и ZIP.

### Как повторить финальный запуск

В терминале VS Code из корня проекта подготовьте локальную папку `data/` по ТЗ и настройте тестовый прокси или стаб по README. Запустите с чистыми зависимостями и отдельной рабочей папкой. Для запуска с платформенным прокси используйте только выданные организаторами параметры доступа.

```powershell
$env:DATA_DIR = (Resolve-Path .\data).Path
$qaRoot = Join-Path $env:TEMP ("energytool-qa-" + [guid]::NewGuid().ToString("N"))
Expand-Archive -LiteralPath .\mts-energytool.zip -DestinationPath $qaRoot
python -m venv "$qaRoot\.venv"
$qaPython = Join-Path $qaRoot ".venv\Scripts\python.exe"
& $qaPython -m pip install -r "$qaRoot\requirements.txt"
New-Item -ItemType Directory -Path "$qaRoot\run" | Out-Null
Push-Location "$qaRoot\run"
Measure-Command { & $qaPython "$qaRoot\solution.py" | Out-Host }
$LASTEXITCODE
Get-Item .\submission.csv
Pop-Location
```

Ожидаются код 0 и CSV внутри `run`. Установка зависимостей выполняется вручную перед локальной проверкой. Сопоставьте результаты с отчётом независимого ревью по C1–C10 и убедитесь, что в README указаны те же команда, переменные и пути.

## Решение о загрузке

- [ ] Проект запускается по README из чистого окружения, архив проверен, контракт CSV проходит.
- [ ] Ни одна существенная рекомендация в проверенных ответах не расходится с базой. Пробелы в retrieval и неуместные уточнения разобраны по отчёту.
- [ ] На живом прокси соблюдён бюджет либо отсутствие доступа явно указано и первый платформенный прогон используется для проверки. Стаб проверяет формат и отказоустойчивость.
- [ ] После загрузки записаны время МСК, хеш, идентификатор или статус, Match Rate, Win Rate и Score при наличии. При 401 обратиться к организаторам, при техническом сбое исправить причину и повторно проверить ZIP с учётом пяти попыток в день.

Сбой запуска, потеря ID, некорректный ZIP, выдуманный продуктовый факт или обещание блокируют загрузку до исправления. Score > 0 нужен для экспертного допуска вместе с материалами и веб-прототипом второго этапа.
