# Moggers_MTS_AI

## МТС EnergyTool

Python MVP консультанта для автоматической проверки на хакатоне. Скрипт должен читать вопросы и базу знаний, подбирать релевантный контекст и формировать `submission.csv`.

- [Техническое задание](docs/MVP-SPEC.md)
- [Архитектура простыми словами](docs/ARCHITECTURE.md)
- [План на сегодня и ручная приёмка](docs/TODAY-CHECKLIST.md)
- [Настройка GitHub, VS Code и Codex](docs/GITHUB-VSCODE.md)

В подготовленной локальной папке «МТС хакатон» рабочая ветка `codex/mvp` основана на `origin/main`. Локальные демо-входы лежат в `data/`, а интерпретатор с тестовой зависимостью — в `.venv/Scripts/python.exe`. На другом компьютере эти файлы нужно подготовить по ТЗ. Данные, окружение и отчёт о точности исключены из Git.

### Запуск и проверки

В чистом окружении установите `python -m pip install -r requirements.txt`. В этой рабочей папке зависимость уже есть в `.venv`. Платформа сама ставит зависимости и передаёт конфигурацию. При локальной проверке укажите адрес, ключ и ID модели прокси, предоставленного организаторами, через `LLM_BASE_URL`, `LLM_API_KEY` и `LLM_MODEL`. При отсутствии доступа можно проверить контракт локальным HTTP-стабом, который запускает тестовый набор.

```powershell
# Запуск с настроенным прокси
.\.venv\Scripts\python.exe solution.py

# Синтетические проверки через локальный HTTP-стаб
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

По умолчанию входы читаются из `data/`. Задайте `DATA_DIR` абсолютным путём, если запускаете из другого рабочего каталога. Результат `submission.csv` создаётся в текущем рабочем каталоге.

Дополнительные алиасы прокси — `OPENAI_BASE_URL`, `OPENAI_API_KEY`, `OPENAI_MODEL` и `GEN_MODEL`. `TEMPERATURE` по умолчанию 0, `MAX_TOKENS` — 2048, `MAX_WORKERS` — 3, `TOP_K` — 12, `RERANKER_TOP_N` — 5. `MVP_ENABLE_RERANK=1` включает дополнительный вызов при заданном `RERANKER_MODEL`. Базовый режим использует BM25 и один штатный генеративный вызов на непустой вопрос. `MVP_DEADLINE_SECONDS` позволяет уменьшить рабочий дедлайн 1080 с для тестирования. `CHUNKER` и `EMB_MODEL` из окружения платформы в этой версии не используются.

### Сборка ZIP

Из корня проекта в PowerShell выполните команду.

```powershell
Compress-Archive -LiteralPath solution.py, contracts.py, retrieval.py, consultant.py, llm_client.py, requirements.txt -DestinationPath mts-energytool.zip -Force
tar -tf .\mts-energytool.zip
Get-FileHash .\mts-energytool.zip -Algorithm SHA256
```

Архив содержит только шесть перечисленных корневых файлов. Перед сдачей повторите проверку из распакованной копии по [чек-листу](docs/TODAY-CHECKLIST.md).

### Подключение к веб-прототипу

Backend может один раз вызвать `load_kb`, `chunk_documents` и `build_index` при запуске. На каждом сообщении он передаёт реплики одной сессии в `extract_query` и вызывает `retrieve`. Функция `build_messages(query, evidence)` формирует запрос к модели. Поле `фрагменты_базы` содержит точные источники после применения лимита контекста. Backend может взять оттуда путь, заголовок и выдержку для режима отладки и отдельно замерить поиск и общее время обработки. Готовый текст проверяет `validate_answer`.

Для следующего этапа backend должен хранить изолированные сессии, историю, источники и тестовые заявки в SQLite. Веб-интерфейс, API сессий, Docker Compose и показ заявки проверяются при сборке веб-прототипа.
